# Day 01 – Introduction to Open Source

## 1. Introduction to Open Source

Open source refers to software whose source code is publicly available for people to view, use, modify, and distribute according to its license.

It allows developers from different parts of the world to collaborate, improve existing software, fix bugs, and build new features.

**Why Open Source?**
- Learn from real-world projects.
- Improve coding and problem-solving skills.
- Collaborate with developers worldwide.
- Gain practical development experience.
- Build a strong developer portfolio.

## 2. Exploring GitHub Repositories

A GitHub repository (repo) is a place where a project's source code, documentation, files, and development history are stored.

Before contributing to a project, it is important to understand its purpose and structure.

**What should you explore?**

- **README.md:** Understand what the project does and how to use it.
- **Source Code:** Explore the project's code and folder structure.
- **Issues:** Find bugs, feature requests, and tasks that need attention.
- **Pull Requests:** Understand the changes proposed by other contributors.
- **CONTRIBUTING.md:** Learn the project's contribution guidelines.
- **LICENSE:** Understand the permissions and conditions for using the project.

## 3. Finding Issues and Feature Requests

Issues are used to track bugs, improvements, questions, and new feature requests in a repository.

They help maintainers and contributors organize the work that needs to be done.

**Common types of issues:**

- **Bug:** Something in the application is not working correctly.
- **Feature Request:** A suggestion to add new functionality.
- **Enhancement:** An improvement to an existing feature.
- **Documentation:** Corrections or improvements to project documentation.

**How to find issues:**

1. Open a GitHub repository.
2. Navigate to the Issues tab.
3. Explore open issues.
4. Look for labels such as `good first issue` or `beginner-friendly`.
5. Read the issue description and understand the expected solution.

Always check whether an issue is still open and whether someone is already working on it.

## 4. Forking Repositories

Forking means creating your own copy of another user's repository under your GitHub account.

It allows you to work on a project independently without directly changing the original repository.

**Why do we fork?**

- To work on someone else's project safely.
- To experiment with code.
- To make changes and improvements.
- To prepare contributions for the original repository.

**Steps to fork a repository:**

1. Open the original GitHub repository.
2. Click the Fork button.
3. Select your GitHub account.
4. GitHub creates a copy under your account.

**Important:** A fork and a clone are different.

- Fork: Creates a copy of a repository on your GitHub account.
- Clone: Downloads a repository to your local computer.

## 5. Understanding Pull Requests

A Pull Request (PR) is a request to merge your proposed changes into another branch or repository.

In open-source contributions, developers commonly submit pull requests from their fork to the original repository.

**Basic Pull Request workflow:**

1. Fork the original repository.
2. Clone your fork to your computer.
3. Create a separate branch.
4. Make the required changes.
5. Commit and push your changes.
6. Open a Pull Request against the original repository.
7. Wait for maintainers to review your changes.
8. Make any requested improvements.
9. Get your PR merged if approved.

**Why are Pull Requests important?**

- They allow maintainers to review code.
- They encourage collaboration.
- They help maintain code quality.
- They provide a clear record of changes.

## 6. Linking Pull Requests with Issues

When working on an issue, it is good practice to link the related Pull Request to that issue.

GitHub supports special keywords that automatically close an issue when the linked PR is merged into the repository's default branch.

**Common keywords:**

- `Fixes #123`
- `Closes #123`
- `Resolves #123`

Here, `123` represents the issue number.

**Example Pull Request description:**

```text
## Description
Fixed the navigation menu alignment issue.

## Changes Made
- Corrected menu spacing.
- Improved responsive alignment.

## Related Issue
Fixes #123
```

**Benefits:**

- Connects code changes with their related issues.
- Helps maintainers track progress.
- Keeps project discussions organized.
- Automatically closes linked issues after a successful merge.

## 7. Open Source Bounties

An open-source bounty is a financial reward offered for completing a particular task, fixing a bug, or implementing a feature.

Some projects and organizations use bounties to encourage developers to contribute.

**How it works:**

1. A project lists a task with a bounty.
2. A contributor checks the requirements and eligibility.
3. The contributor works on the task.
4. The solution is submitted for review.
5. If the contribution meets the project's conditions, the reward may be provided.

**Important considerations:**

- Read the bounty rules carefully.
- Check whether the task is still available.
- Understand the expected solution.
- Follow the project's contribution guidelines.
- Never assume that opening a PR guarantees payment.

Open-source contributions are valuable even when no financial reward is involved.

## 8. Professional Communication and Collaboration

Communication is an important part of open-source development because contributors often work with people from different backgrounds and locations.

Professional communication helps build trust and makes collaboration easier.

**Best practices:**

- Read the documentation before asking questions.
- Explain bugs and problems clearly.
- Write meaningful commit messages.
- Keep Pull Request descriptions concise.
- Be respectful when interacting with maintainers.
- Respond politely to code review feedback.
- Avoid creating duplicate issues.
- Be patient while waiting for reviews.

**Example of a professional issue comment:**

"I would like to work on this issue. I have reviewed the problem description and would be happy to contribute a solution. Please let me know if there are any specific requirements."

## Key Takeaways

- Open source encourages collaboration and shared development.
- GitHub repositories help developers manage projects.
- Issues identify bugs, improvements, and new features.
- Forking creates an independent copy of a repository.
- Pull Requests allow contributors to propose changes.
- Linking PRs with issues improves project tracking.
- Bounties can provide financial incentives for contributions.
- Professional communication makes collaboration effective.
